# API и контракт провайдера

## Доступ

Бизнес-маршруты `/api/v1/*` и `/metrics` используют `X-API-Key`. В `APP_ENV=production` ключ обязателен и должен содержать не менее 32 символов; `DEBUG` должен быть выключен. В локальной среде отсутствие ключа допускается для разработки на loopback.

Ключ идентифицирует доверенный сервис, а не конечного пользователя. Вызывающее приложение обязано авторизовать `user_id` до отправки запроса. Используйте TLS между сервисами и храните ключ вне образа и репозитория.

`/health` и `/ready` доступны без ключа. `/health` проверяет жизнь процесса; `/ready` проверяет доступность PostgreSQL и брокера и возвращает `503`, когда сервис не готов принимать работу.

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `POST /api/v1/users/` | Открыть внутренний счёт с начальным балансом |
| `GET /api/v1/users/{user_id}` | Получить баланс, резерв и доступную сумму |
| `POST /api/v1/payments/deposit` | Принять намерение пополнения |
| `POST /api/v1/payments/withdraw` | Принять намерение списания и зарезервировать сумму |
| `GET /api/v1/payments/{payment_id}` | Получить состояние операции |
| `GET /api/v1/dlq?limit=50&offset=0` | Посмотреть окончательно отклонённые операции |
| `GET /api/v1/metrics` | Диагностические метрики в JSON |
| `GET /metrics` | Метрики в формате Prometheus |

Точные схемы запросов, ответов и коды статусов доступны в OpenAPI `/docs`. Денежные поля в ответах сериализуются десятичными строками для сохранения точности.

Для обоих платёжных POST обязателен `Idempotency-Key`: 1–64 печатных ASCII-символа, значение не должно состоять из пробелов. Используйте один ключ на одно бизнес-намерение; сохраняйте его на вызывающей стороне до первого запроса.

```http
POST /api/v1/payments/deposit
X-API-Key: <service-secret>
Idempotency-Key: order-42-deposit-1
Content-Type: application/json

{"user_id":1,"deposit":"100.00"}
```

Типовые ошибки:

| Код | Значение |
|---|---|
| `401` | Неверный либо отсутствующий сервисный ключ |
| `404` | Пользователь или платёж не найден |
| `409` | Ключ уже связан с другой операцией/суммой или нарушено ограничение уникальности |
| `422` | Невалидные поля, денежная точность или ключ повторного запроса |
| `503` | Временная недоступность инфраструктуры |

Недостаточный доступный остаток отклоняет списание с `409`. Соответствующий платёж сохраняет `failed`; его повтор с тем же ключом возвращает тот же результат.

## Состояния платежа

| Состояние | Значение |
|---|---|
| `new` | Намерение принято и ожидает обработки |
| `processing` | Обрабатывается или ожидает выяснения результата |
| `success` | Результат провайдера применён к балансу |
| `failed` | Получен окончательный отказ; резерв снят |

После принятия запроса следует опрашивать статус по `payment_id`. Для `processing` с `last_error`, начинающимся на `reconciliation_required`, нужна операционная проверка. Не создавайте новую операцию, чтобы обойти этот статус.

## HTTP-контракт шлюза

Приложение использует адаптер `app.infrastructure.payment_gateway.http.PaymentGatewayClient`. Адрес `PAYMENT_GATEWAY_URL` — базовый; запрос отправляется на `<base>/pay`.

```http
POST /pay
Idempotency-Key: <namespace>:123
Content-Type: application/json

{"payment_id":123,"user_id":1,"amount":"100.00","commission":"2.00","type":"withdraw"}
```

Ожидаемый подтверждённый успех:

```json
{"status":"success","payment_id":123}
```

Одного `2xx` без валидного подтверждения недостаточно. Адаптер классифицирует подтверждённый отказ отдельно от временной ошибки или неизвестного результата. При настройке `GATEWAY_API_KEY` адаптер передаёт `Authorization: Bearer <secret>`. Для другого формата авторизации адаптер изменяется под контракт конкретного провайдера.

Реальный провайдер должен обеспечивать устойчивую идемпотентность по переданному ключу, проверять совпадение payload, хранить результат достаточно долго и предоставлять способ выяснить исход операции по этому ключу. Изменение `GATEWAY_IDEMPOTENCY_NAMESPACE` после запуска меняет пространство ключей; для незавершённых платежей оно недопустимо.

Тестовый шлюз запускается профилем `dev`, хранит квитанции в PostgreSQL и предназначен для локальных проверок. Он не является платёжным провайдером. Для подключения конкретного провайдера адаптер должен соответствовать его контракту, авторизации и правилам выяснения неопределённых результатов.
